# 进程与 CPU：一个 CPU 怎样服务多个程序

## 1. 进程保存什么

一个进程有地址空间、执行上下文（寄存器、程序计数器等）以及打开文件等资源。就绪态可以运行但还没有获得 CPU；运行态正在执行；阻塞态在等 I/O 等事件。I/O 完成通常先变为就绪，之后才由调度器选中。

应用的大部分普通指令直接在用户态 CPU 上执行。特权操作经系统调用进入内核；时钟中断让内核有机会重新调度，防止一个程序永远占用 CPU。异常也可以同步进入内核，例如缺页。

## 2. fork、exec、wait

`fork` 创建子进程，它具有独立的地址空间，初始内容来自父进程。Linux 通常用写时复制延迟复制物理页；“逻辑独立”不等于 fork 当场复制全部物理内存。

`exec` 在同一进程中装入新程序，PID 保持不变。`waitpid` 获取子进程退出状态并回收其退出记录。子进程已退出但尚未被回收时，可以处于僵尸状态。

fork 后继承的描述符可以引用同一个内核打开文件对象，因此普通文件的偏移量可以共享；这与普通变量的隔离形成对照。fork 前未刷新的 stdio 用户态缓冲也可能被复制，因此实验显式关闭输出缓冲。

## 3. 调度指标

设到达时间 A、首次运行时间 S、完成时间 C、CPU 总服务时间 B：

- 响应时间 = S − A，关注多久第一次得到执行机会。
- 周转时间 = C − A，关注多久全部完成。
- 对无 I/O 的简化模型，等待时间 = C − A − B。

FIFO 简单，但长任务可以阻塞后面的短任务。SJF 在所有任务同时到达、运行时长已知、无抢占且忽略开销的模型下最小化平均周转时间。实际通常无法提前精确知道时长。

RR 按时间片轮转，较小的时间片可以改善首次响应，但增加切换开销。MLFQ 根据历史运行行为调整优先级，试图兼顾短任务响应和长任务进展；需要优先级提升等规则缓解饥饿，也需要累计 CPU 用量避免任务通过频繁让出 CPU 占便宜。

## 4. 手算例子

三个任务 A=5、B=2、C=1，全部在 t=0 到达，切换开销为零。

| 算法 | 执行区间 | 响应时间 A/B/C | 周转时间 A/B/C |
| --- | --- | --- | --- |
| FIFO | A:0–5，B:5–7，C:7–8 | 0/5/7 | 5/7/8 |
| SJF | C:0–1，B:1–3，A:3–8 | 3/1/0 | 8/3/1 |
| RR，q=2 | A:0–2，B:2–4，C:4–5，A:5–7，A:7–8 | 0/2/4 | 8/4/5 |

用实验 3 核对后再改时间片。思考：哪种算法平均响应最短，哪种平均周转最短？答案取决于任务集合和模型，不能把一个例子的结果推广成所有场景的结论。
