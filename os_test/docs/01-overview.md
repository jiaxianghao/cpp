# 知识地图：操作系统提供了什么

操作系统在应用与硬件之间提供抽象、隔离和资源管理。复习时总问三个问题：应用看到了什么抽象？内核怎样实现？多个应用竞争或故障发生时会怎样？

| 主线 | 应用看到的抽象 | 关键机制 | 策略问题 |
| --- | --- | --- | --- |
| CPU 虚拟化 | 进程似乎独占 CPU | 特权级、时钟中断、上下文切换 | 下一段时间让谁运行 |
| 内存虚拟化 | 每个进程有自己的地址空间 | 页表、TLB、异常、保护位 | 内存紧张时淘汰哪一页 |
| 并发 | 多个执行流共同完成任务 | 锁、原子操作、条件变量 | 如何保持不变量并减少等待 |
| 持久化 | 文件在程序退出后仍存在 | 目录、inode、块分配、日志 | 如何兼顾性能和恢复能力 |

```text
应用：进程 / 线程 / 指针 / 文件描述符
                  │ 系统调用、异常、中断
内核：调度 / 虚拟内存 / 同步 / 文件系统 / 驱动
                  │
硬件：CPU / RAM / 存储设备
```

## 最容易混在一起的几个概念

- 程序是静态代码；进程是运行中的程序实例及其资源。线程是进程内的执行流。
- 机制回答“怎么做到”，策略回答“选哪一个”。上下文切换是机制，RR 是策略。
- 系统调用进入内核，不一定换进程；进程切换则需要保存和恢复执行上下文。
- 并发是任务执行时间交错；并行是同一时刻有多个任务在执行，单核也有并发。
- 快不等于正确。未加锁代码跑出正确数字，不能证明没有竞态。

## 实验需要的 C 知识

`fork()` 返回两次：父进程拿到子 PID，子进程拿到 0，失败时返回 -1。`exec` 成功时替换当前进程的程序映像，不返回原来的代码。`waitpid` 回收子进程退出状态。

文件描述符是进程里的整数索引；0、1、2 通常分别是标准输入、输出和错误。`read` 返回 0 通常表示 EOF，返回 -1 表示错误。一次 `read/write` 不保证完成全部请求长度。

`pthread_create` 启动线程，`pthread_join` 等待其结束。线程函数通常返回 `void *`。线程共享进程内的全局变量，但各自有栈；栈上的对象也可以通过指针被其他线程访问，必须管理好生命周期和同步。

如果这些函数看起来陌生，先阅读 `labs/process.c` 的注释，运行后逐行对照。无需先学完整的 C 或 Linux 内核源码。
