# 闭卷自测

每题 0～2 分。建议先把答案写到学习记录，再展开参考答案。四组各 8 分，总分 32 分。

## 进程与 CPU

1. fork 后子进程修改普通变量，父进程能看到吗？相同数值的指针说明什么？
2. exec 会创建新 PID 吗？wait 有什么用途？
3. 系统调用一定发生进程切换吗？就绪态与阻塞态有什么区别？
4. A=5、B=2、C=1 全部在 t=0 到达，RR 时间片为 2、切换开销为零，求每个任务的响应和周转时间。

<details>
<summary>参考答案 1～4</summary>

1. 普通私有变量不共享，父进程保持原值。相同数值只是相同虚拟地址，不能推出相同物理对象。显式共享映射是另一种情况。
2. exec 替换当前进程程序映像，PID 不变。wait 获取退出状态并回收子进程退出记录。
3. 不一定，系统调用可以在同一进程上下文中执行后返回。就绪态等 CPU，阻塞态等事件，事件未发生时即使有空闲 CPU 也不能继续相应执行。
4. 顺序 A:0–2、B:2–4、C:4–5、A:5–7、A:7–8。响应 0/2/4，周转 8/4/5。

</details>

## 内存

5. 4 KiB 页中，虚拟地址 `0x12345` 的页号和偏移是什么？映射到 PFN 9 后物理地址是什么？
6. TLB miss 为什么不一定要读磁盘？缺页又为什么不一定要读磁盘？
7. malloc 成功是否意味着所有页面驻留物理内存？free 后为什么不能再用原指针访问？
8. FIFO 和 LRU 在命中时有什么区别？增加页框为何可能让 FIFO 缺页更多？

<details>
<summary>参考答案 5～8</summary>

5. VPN=`0x12`，offset=`0x345`，物理地址=`0x9345`。
6. TLB miss 只是转换缓存未命中，页表可能指出页面已驻留。缺页可能只需分配零页、做写时复制，也可能是非法访问，不能统称为交换读盘。
7. 不保证全部驻留，可能按需分配；free 后对象生命周期结束，继续访问已释放对象属于未定义行为，即使数据暂时没变。
8. FIFO 命中不更新装入顺序，LRU 更新最近使用顺序。FIFO 不具有 LRU 的栈性质，不同容量下淘汰轨迹不同，可出现 Belady 异常；能举出实验中的 9/10 次缺页即可。

</details>

## 并发

9. `volatile int counter` 能使多线程的 counter++ 正确吗？原子 load 加原子 store 呢？
10. 条件变量等待为什么通常用 while？wait 如何处理互斥锁？
11. 死锁的四个必要条件是什么？如何消除 AB/BA 的循环等待？
12. 条件变量与信号量有什么区别？通知早于 wait 时会怎样？

<details>
<summary>参考答案 9～12</summary>

9. volatile 不提供线程同步。拆开的原子 load/store 可以避免该对象上的数据竞争，但整个更新仍可能丢失；用 atomic_fetch_add 或覆盖完整操作的锁。
10. 要处理虚假唤醒和条件被其他线程改变。wait 原子地释放锁并等待，返回前重新获得锁，再检查共享谓词。
11. 互斥、占有并等待、不可抢占、循环等待。规定所有线程按同样顺序获取 A/B，可打破循环等待。
12. 条件变量不积累计数，过去的 signal 不保证未来 wait 直接返回，但共享谓词可以保留事实；信号量 post 增加计数，之后的 wait 可以消费额度。

</details>

## 持久化

13. 文件名、inode、文件描述符各自表示什么？rename 替换后旧 fd 为什么能继续读旧文件？
14. write、用户态 flush、文件 fsync 和目录 fsync 分别解决什么？
15. “临时文件 + rename”为什么不能单独证明掉电安全？本包实验验证了什么，没有验证什么？
16. 文件系统日志解决什么问题？为什么 RAID 和日志都不能代替备份？

<details>
<summary>参考答案 13～16</summary>

13. 名字在目录中标识文件，inode 保存文件元数据及数据定位信息，fd 引用打开文件资源。替换路径绑定不会把已打开的旧对象自动改成新对象。
14. write 通常将数据交给内核；flush 把语言运行库的缓冲交给下层；文件 fsync 请求同步文件数据和相关元数据；目录 fsync 用于同步目录项变更。
15. 原子可见与掉电持久是不同保证，还需同步数据和目录并考虑文件系统与设备语义。本实验验证正常运行中的旧 fd/新路径行为和同步调用完成，没有验证断电恢复。
16. 日志帮助恢复多步更新后的结构一致性；不等于保存历史版本或保证任意应用事务。RAID 可以容忍特定设备故障，但误删或错误写入仍会传播，日志也通常不能恢复任意历史内容。

</details>
