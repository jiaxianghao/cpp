# RAII 与所有权

## 核心回顾

RAII 把资源获取和释放绑定到对象生命周期。资源可以是内存、文件、锁或连接。正常返回和异常栈展开都走同一条析构路径，所以清理不会依赖每条分支都记得调用 close/delete。

默认选择值对象；需要动态独占所有权时用 `unique_ptr`；确实存在共同所有者时才用 `shared_ptr`。`weak_ptr` 是对共享对象的不拥有引用，通过 `lock()` 获取本次访问期间的临时共享所有权。不能仅凭 `expired()` 为 false 就假定下一次访问一定有效。

接口应表达意图：`T&` 表示必须存在的借用，`T*` 可表达允许为空的借用，按值接收 `unique_ptr<T>` 表示接管资源，按值接收 `shared_ptr<T>` 表示参与共享所有权。只需要观察对象时不必强迫调用者使用某一种智能指针。

两个对象互持 shared_ptr 会形成无法自动打破的拥有环。某一方向不需要拥有时应改成 weak_ptr。shared_ptr 的计数管理不等于其所指对象的业务数据自动线程安全。

## 先预测

1. owner 移动后，资源析构了没有？
2. 抛出异常后 Resource::alive 为什么归零？
3. parent.reset() 后 child 还存在，为什么父对象仍能销毁？

## 实验与解读

运行 `./build/02_ownership`。检查证明所有权转移不销毁对象，异常路径释放资源，弱引用不延长父对象寿命。不要保存 observer 到所有者销毁之后再解引用。

## 动手练习

写 `inspect(const Resource&)` 和 `consume(std::unique_ptr<Resource>)`，比较调用方式。给 Node 添加只在父对象存在时执行的操作，使用 `if (auto p = parent.lock())`。
