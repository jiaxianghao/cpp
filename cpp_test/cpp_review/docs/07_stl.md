# 容器、算法与 lambda

## 核心回顾

vector 的连续存储方便遍历，但扩容会使元素的指针、引用和迭代器失效；没有重分配不等于所有操作都稳定，erase 会使删除位置及之后的迭代器和引用失效。reserve 改变容量，resize 改变元素个数。别用 reserve 后直接下标写尚不存在的元素。

remove_if 将保留元素移动到前面，返回新的逻辑末尾，不改变容器 size；尾部内容不再代表要保留的序列，随后用 erase 真正删除。C++17 经典写法是 erase-remove，读算法时要区分逻辑范围和容器拥有的对象个数。

lambda 按值捕获保存当时的值，按引用捕获访问原对象。引用捕获不会延长被捕获对象寿命；返回一个捕获局部变量引用的回调会悬空。捕获 this 也不等于拥有对象。

默认先选择简单的容器与算法，再根据访问方式、失效规则和实测性能调整。不要只凭某个操作的大 O 就断言 list 一定比 vector 快；分配和缓存局部性也会影响真实结果。

3. 修改 threshold 后，两个 lambda 为什么给出不同结果？
