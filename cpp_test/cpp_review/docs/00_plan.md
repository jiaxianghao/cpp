# 六周复习计划

目标是能解释、预测、修改并验证代码，而不只是看完笔记。先用本计划恢复主干，再回到原书查薄弱点。不同版次条款编号不同，下面按主题定位。

每天建议：10 分钟闭卷回忆，15 分钟阅读，20 分钟实验，10 分钟写下结论。每个主题在次日、约一周后、约三周后各用 5 分钟复述一次。忘记是定位复习点的信号。

## 第一天闭卷诊断（20 分钟）

不用查资料，写出自己的解释和一个小例子：

1. 成员初始化顺序由谁决定？构造失败会调用哪些析构？
2. RAII 与智能指针分别解决什么？裸指针一定表示所有权吗？
3. `std::move` 到底执行了什么？对 const 对象 move 会怎样？
4. 为什么按值传递基类可能破坏多态？虚析构什么时候必要？
5. 基本保证和强保证有什么区别？`noexcept` 会阻止函数抛异常吗？
6. `T&&` 什么时候是转发引用？有名字的右值引用变量表达式是什么类别？
7. `vector` 扩容后哪些东西失效？`remove_if` 为什么不缩小 size？
8. 重构与增加功能如何区分？没有测试时第一步是什么？
9. Strategy 与 State 有什么区别？什么场景不用模式反而更好？
10. 回调捕获对象引用后，如何判断生命周期是否安全？

每题 0～2 分：0=不能解释；1=能说结论但不能举例；2=能用例子解释适用条件。分数仅用于分配时间，不是跳过实验的理由。

## 第四周经典原则速记

- `explicit` 阻止非预期的隐式转换；单参数构造函数应思考是否真的允许自动转换。
- 把不需要访问私有状态的辅助操作写成非成员函数，可减少类接口负担。
- `new[]` 与 `delete[]` 必须配对；日常优先 `vector`、`string`、`unique_ptr`。placement new 不分配存储，别把它与普通 new 混淆。
- `static_cast` 用于有依据的静态转换；`dynamic_cast` 用于多态层次的运行时检查；`const_cast` 不让原本 const 的对象变成可合法修改；`reinterpret_cast` 不保证对象布局兼容。
- `inline` 不保证内联调用；不要从关键字直接推断性能。先保证语义正确，再针对真实负载测量。
- 编译依赖很重时才考虑 Pimpl；只有复制语义昂贵且需求明确时才讨论写时复制等复杂技巧。
