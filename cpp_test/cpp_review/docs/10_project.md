# 综合项目：订单计价、重构与异常保证

这是一个可直接运行的完整基线，以及供你练习的任务清单。源码：[project/checkout.cpp](../project/checkout.cpp)。

## 已实现的规则

- 金额以整数“分”表示，输入非负，所有中间运算均不溢出 int。
- 小计等于各商品单价乘数量之和。
- 普通客户无折扣；会员打九折，整数截断。
- 折后不足 10000 分收 800 分运费，否则免费。
- 提交成功后保存应收金额；策略失败时原收据列表不变。
- 空订单沿用练习旧行为，收 800 分运费；需要改变时作为单独需求处理。

这里没有接入支付、数据库或网络。强保证只针对 Checkout 内部收据列表，不声称对任意策略的外部副作用回滚。

## 结构与理由

legacy_quote 留作迁移比较；subtotal 提炼稳定计算；quote 接收 Discount 策略；Checkout 负责记录结果。vector 管理资源，遵循 Rule of Zero。折扣只有一个操作，lambda 加 std::function 已足够，没有为它建立虚基类。

submit 先计算金额，再向 vector<int> 插入；计算抛出时状态尚未改变，插入分配失败时 vector<int> 保持原状。测试注入策略异常并检查前后状态；并未强制模拟分配器耗尽，后者的论证依赖容器保证。

```bash
cmake --build build --target 10_checkout
./build/10_checkout
ctest --test-dir build --output-on-failure
```

基线输出：`regular=10000, member=9800; failed checkout leaves receipts unchanged`。

## 第一阶段：解释现有代码

手算普通和会员订单；指出折扣发生在运费计算之前；解释金额为什么使用整数；列出哪些输入假设使 int 足够用于这个练习。说明旧实现与新实现一致，不等于现实业务规则一定合理。

## 第二阶段：先测试，再增加规则

新增需求：折前满 20000 分减 2000 分，不与会员折扣叠加，然后仍按折后金额判断运费。先补以下独立期望，再新增策略，quote 不应修改。

|折前金额|折后金额|最终金额|
|---|---|---|
|19999|19999|19999|
|20000|18000|18000|
|22000|20000|20000|
|9999|9999|10799|

不要为了这些输入增加通用优惠券规则引擎。完成后再讨论什么时候规则组合真的需要新结构。

## 第三阶段：增强异常验证

测试第一次提交失败时列表为空；已有两条收据时失败，列表内容和顺序保持；失败之后再次成功提交可正常追加。每个测试都要证明异常实际发生，而不只比较空列表。

## 第四阶段：行为保持的整理

把运费提炼成具名函数。保留所有业务期望和前后对比检查。每次只改一个结构，然后运行测试。不要在这次重构里改变空订单规则。
