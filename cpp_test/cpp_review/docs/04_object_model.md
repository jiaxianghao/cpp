# 对象模型与多态

## 核心回顾

类的语义由语言规定，内存布局的很多细节由 ABI 和实现决定。成员可能有对齐填充；有虚函数的对象通常借助虚表指针实现动态派发，但标准没有要求某一张虚表、固定位置的 vptr 或具体字节大小。不要用强制转换读取所谓虚表来证明标准结论。

按值传入 Base 只构造 Base 对象，派生部分被切掉；通过 Base 引用/指针调用虚函数才保留派生对象身份。非虚成员按静态类型选择，虚函数按动态类型派发。编译器在能确定类型时可能去虚拟化，动态语义不意味着每次都必须间接调用。

构造和析构期间虚调用受当前构造/析构层级限制。Base 构造函数中调用 kind() 会调用 Base 的实现，此时 Derived 尚未构造完成。不要在构造函数中期待调用派生类定制逻辑。

通过基类指针 delete 派生对象时，常规多态所有权接口需要虚析构；另一种设计是禁止通过基类删除，例如受保护的非虚析构。`override` 让编译器检查是否真的覆盖了基类虚函数。默认参数按静态类型选择，避免给虚函数设置不一致的默认参数。

public 继承应表达“能替代基类”的契约；只是想复用几行实现时，优先组合。多重继承可能涉及基类子对象地址调整；本轮只理解原因，不假定偏移。
