## 动手练习提示

- 01：内层对象在内层作用域结束时销毁，外层对象随后销毁。错误返回局部引用不要运行。
- 02：consume 调用通常需要 `consume(std::move(owner))`；inspect 只借用，不改变拥有关系。
- 03：去掉 noexcept 后常观察到复制；一个只含 vector 的类默认复制已经拥有独立容器，无需手写资源管理。
- 04：容器元素必须为拥有多态对象的指针或其他合适包装，不能把派生值直接放进 vector<Base> 并期待保留派生部分。
- 05：给失败点分别编号，对每个失败点保存旧状态并在 catch 后比较；必须同时检查确实捕获到异常。
- 06：新增 `category(const int&)` 后，const 左值保留 const 引用，选择该重载。
- 07：删除小于 4 的元素后应为 4、5、6；返回捕获局部值的闭包不依赖局部变量继续存在。
- 08：practice 每次提炼都要参与同一批行为检查；空订单收费改成 0 应独立修改期望和业务逻辑。
- 09：SmsApplication 只需覆写 create_sender；新策略只需要满足输入/输出与语义契约；增加模式应解决具体变化问题。
- 10：新折扣策略可写为 `[](int n) { return n >= 20000 ? n - 2000 : n; }`，不应修改 quote 的运费顺序。

1～7 的要点见 01～07。第 8 题：先固定现有行为并确认关键边界，再做小步结构修改。第 9 题：Strategy 更关注算法替换，State 更关注状态驱动行为与转换；简单稳定规则优先直接函数。第 10 题：检查回调可能执行的最晚时刻，被引用对象是否仍存在，是否涉及异步、退订或跨线程；智能指针也需要明确是拥有还是观察。

## 常见错误说法纠正

- “move 后肯定为空”：仅适用于有明确契约的类型；本例 Value 的约定是 -1。
- “const 就没人能改”：const 访问路径不代表不存在其他可写别名。
- “析构一定能兜底”：对象必须由正确的所有者管理，构造失败的完整对象析构不会调用。
- “noexcept 里面不能 throw”：可以编译某些抛出路径，但异常若逃出边界将 terminate。
- “强保证意味着任何副作用都撤销”：需要明确保证范围，外部 I/O 不会自动撤销。
- “多加模式就更容易维护”：间接层也有成本，只解决真实变化。
