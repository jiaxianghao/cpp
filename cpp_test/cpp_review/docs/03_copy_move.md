# 复制、移动与值语义

## 核心回顾

复制建立独立的值；移动允许接收方复用源对象资源。`std::move` 本质上是转换表达式的值类别，它本身不转移资源。真正的动作取决于随后选择的构造函数或赋值运算符。

Rule of Zero：成员已经正确管理资源时，优先不声明特殊成员函数。手写资源所有者才需要整体考虑析构、复制构造、复制赋值、移动构造、移动赋值（Rule of Five）。这不是要求每个类都手写五个函数。用户声明析构函数会影响隐式移动成员的生成。

移动后状态应查类型契约。标准库对象通常处于有效但未指定状态（有具体规定的类型除外）；不要假定所有移动后的 string/vector 都为空。示例中 number=-1 是我们自己的明确约定。移动 const 对象常退化为复制，因为典型移动构造需要可修改源对象的 `T&&`。

`noexcept` 移动有助于容器在重分配时维持异常保证。若移动可能抛出且可以复制，vector 的实现常选择复制。不要为获取性能把实际可能抛出的操作错误标注为 noexcept。

C++17 对某些纯右值场景保证复制消除，例如 `return T{};`；具名局部变量的 NRVO 仍是可选优化。`return std::move(local);` 可能阻碍 NRVO，通常直接 return local。

## 先预测

1. `auto&& reference = std::move(source)` 是否调用移动构造？
2. `std::move(immutable)` 为什么调用复制构造？
3. vector 重分配为什么会关注 noexcept？

## 实验与解读

运行 `./build/03_copy_move`。显式复制/移动的语义由 CHECK 固定；最后输出容器重定位的观察计数。GCC/libstdc++ 通常显示 copies=0、moves=1，不将该计数当成所有实现必须遵守的固定输出。

## 动手练习

去掉移动构造的 noexcept，重新观察重分配计数。随后恢复。再创建一个只含 vector<int> 的值类，不写五个特殊函数，验证复制后修改一方不会改变另一方。
