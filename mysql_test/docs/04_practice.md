复制下面的模板，不必写长篇笔记。

```text

```

例：我以为 `WHERE user_id=42 ORDER BY created_at` 能直接使用联合索引顺序；实际出现额外排序。因为 status 在 created_at 前面，同一用户的不同状态分别按时间排序，整体时间并不有序。

## 复习节奏建议

- 第 2 天开始前：不看文档，回答昨天最不确定的 3 个问题。
- 完成全部实验后隔 3 天：只重做两个预测错过的实验。
- 隔 1 周：闭卷画“查询链路”和“更新/提交链路”，重做自测。
- 隔 1 个月：从空库重新设计一个小例子，解释索引与事务选择。

这是便于执行的安排，不要求机械遵守某个天数。每次把时间花在解释不清的地方。

## 第二轮的小练习：实现安全转账

先用 SQL 完成即可，需要时再用熟悉的 C++ 写调用程序。

明确需求：账户 1 向账户 2 转账 100；余额不足时不允许转账；两笔修改一起提交。用同一个连接执行：

```sql
START TRANSACTION;
UPDATE accounts SET balance=balance-100
WHERE id=1 AND balance>=100;
SELECT ROW_COUNT();
-- 只有返回 1 才继续；返回 0 则执行 ROLLBACK 并停止。
UPDATE accounts SET balance=balance+100 WHERE id=2;
SELECT ROW_COUNT();
-- 也必须返回 1，否则 ROLLBACK。
-- 手动检查两个结果均为 1 后再 COMMIT。
```

上面是手动实验步骤，注释不具备条件分支功能，不能不看结果直接一路执行。应用程序要读取 affected rows，在任何一步失败时回滚，全部满足条件才提交。

验证三个场景：正常转账后总额不变；余额不足时两侧均不变化；目标账户不存在时扣款被回滚。做完恢复实验数据。

继续回读原书时，用这些主题定位：记录结构与数据页 → B+ 树索引 → 单表/连接访问与成本 → Buffer Pool → redo/undo → 事务、MVCC 和锁。不要求书中章节编号与此材料一一对应。
