# 综合项目：任务依赖分析器

建议在 24 周主线后，用 10 次、每次 30 分钟完成。第 24 周只做需求和图示。项目是留给你的独立实践，当前仓库提供需求、样例、验收标准和可复用的算法示例，不提供现成项目答案。

## 最小功能

给定一组任务时长和有向依赖：u→v 表示 v 必须等待 u 完成。输出是否存在环；无环时输出一个合法执行顺序、每个任务的最早开始时间及全部任务的最早完成时间。

**假设任务可无限并行、时长为非负整数、没有资源冲突、输入编号合法。** 时间用 long long。先不加入线程、网络、数据库或界面。

输入格式：第一行 n m，第二行 n 个任务时长，后面 m 行 u v。n=0 时第二行可省略。重复依赖按多条边一致处理或读入时去重，但入度统计和删除必须对应。

样例：

```text
4 4
3 2 4 1
0 1
0 2
1 3
2 3
```

一个合法拓扑序为 `0 1 2 3`（也允许 `0 2 1 3`）。最早开始时间为 `0 3 3 7`，最早完成时间为 8。任务 3 需要等前驱 1 和 2 都完成，所以取最大结束时间，不能相加。

有环输入：

```text
2 2
1 1
0 1
1 0
```

应报告 `CYCLE`，不把部分顺序当完整结果。空图完成时间为 0；无依赖时所有任务同时开始，整体完成时间是最大时长。

## 十次学习拆分

| 次数 | 单次任务 | 验收 |
|---|---|---|
| 1 | 读需求，画样例依赖图 | 手算开始/结束时间 |
| 2 | 设计数据结构与函数输入输出 | 写明 V/E 与存储复杂度 |
| 3 | 实现输入与邻接表 | 样例边和入度正确 |
| 4 | 实现 Kahn 拓扑排序 | 孤立点也被处理 |
| 5 | 加处理数判断环 | 环样例输出 CYCLE |
| 6 | 定义 earliest_start 状态并写转移 | 多前驱取 max |
| 7 | 输出结果与整体时间 | 样例结果 8 |
| 8 | 加空图、无边、链、零时长检查 | 所有期望一致 |
| 9 | 独立检查、解释复杂度 | 时间/空间 O(V+E) |
| 10 | 闭卷讲解并整理错题 | 能解释为什么按拓扑序计算 |

算法提示：起点 earliest_start=0；按拓扑顺序处理 u，对每条 u→v 更新 `earliest_start[v]=max(earliest_start[v],earliest_start[u]+duration[u])`。依赖满足后再处理 v；这也是 DAG 上的动态规划。

## 验收清单

- 样例四节点输出合法拓扑序，开始时间 `0 3 3 7`、结束时间 8。
- 链 0→1→2、时长 2/3/4，开始时间 0/2/5，整体 9。
- 三个孤立点、时长 2/5/1，整体 5。
- 两点成环和自环均报告 CYCLE。
- 空图整体 0；只有一个零时长点整体 0。
- 拓扑序的测试按边约束验证，允许多个合法顺序。
- 能解释 BFS 距离、Dijkstra 距离与本题“最早开始时间”的不同含义。

先完成这些，再考虑选学扩展：记录决定最早开始的前驱并恢复关键路径。固定线程数下的调度是另一个问题，不能把无限并行答案直接当作实际执行时间。
