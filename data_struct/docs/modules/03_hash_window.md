# 03 哈希、双指针与滑动窗口（第 5–6 周）

先修：数组、前缀和。目标：知道查找表保存什么，也知道窗口能否单向移动。

## 1. 哈希是用空间换查找

哈希函数把键映射到桶，不同键可能碰撞。常见处理是链式/桶内结构或开放寻址。负载因子是元素数与桶数之比，太高会增加冲突；扩容重哈希有额外成本。

`unordered_map` 常见查询、插入的平均复杂度为 O(1)，最坏可能 O(n)。`map` 提供有序键和 O(log n) 的基本操作。只有需要顺序时才为顺序付出代价；不能依赖 unordered_map 的遍历顺序。

两数之和的一次扫描：查找 target−x 是否已经出现，再把 x 和下标放入表中。先查后插避免同一元素与自身配对。

## 2. 双指针需要可证明的移动规则

有序数组两数之和：若左右和太小，右指针左移只会更小，因此排除当前左端，left++；和太大则 right--。没有排序时这条推理不成立。

原地去重的快慢指针含义不同：读指针扫描全部元素，写指针划定已保留结果。两者都只前进，时间 O(n)。

## 3. 最长不重复子串

窗口 `[left,right]` 中不允许重复。记录字节最近出现位置 `last[c]`；遇到 c 时更新 `left=max(left,last[c]+1)`。必须取 max：旧重复可能已经在窗口外，left 不可倒退。

以 `abba` 为例：

| right / 字节 | left | 当前窗口 | best |
|---|---|---|---|
| 0 / a | 0 | a | 1 |
| 1 / b | 0 | ab | 2 |
| 2 / b | 2 | b | 2 |
| 3 / a | 2 | ba | 2 |

哈希实现平均 O(n)，空间 O(min(n,字节种类数))。本项目按字节统计，不能直接当作 Unicode 字符算法。

## 4. 有负数的区间和计数

找和为 k 的连续子数组，需要 `p[r]-p[l]=k`，等价于统计此前多少个前缀等于 `p[r]-k`。表中存次数，不只是“存在”。初始化 `{0:1}` 表示空前缀。

数组 `[1,-1,0]`、k=0：处理前缀 1 不增加；处理前缀 0 增加 1；再处理 0 增加 2，总数 3。先查再增加当前前缀计数，避免把当前空区间算入。

带负数时，“和太大就缩左边”没有单调性，不能直接套正数窗口；删去负数会让和更大。前缀和+哈希平均 O(n)、空间 O(n)。
