# 《程序员的自我修养——链接、装载与库》复习实验室

适合读过书、现在希望通过动手重新串起知识的 C/C++ 开发者。这里是原创复习笔记与实验，不是原书摘录或逐章替代品。

默认学习节奏：**两周，每天 45～60 分钟**。实验以当前 Linux x86_64 + GCC/GNU binutils 环境为基准；重点是 ELF。书中 Windows PE/COFF、DLL 的专门机制不在本轮实操范围内。汇编语法、重定位类型和运行库细节不能直接套到其他架构。

## 从这里开始

```bash
cd /home/uisee/cpp/prodgram_build_link
make all
./build/01/app
```

预期打印 `value=21`。随后打开 [14 天计划](docs/00_plan.md)，从第 1 天开始。不要一口气读完所有笔记；先预测实验结果，再运行，再解释差异。

需要验证全部材料时运行：

```bash
make check
```

它会构建并运行 8 组实验，检查正常输出，以及缺失符号、重复定义、静态库顺序、插件加载/导出失败和 C/C++ 链接不匹配等预期错误。错误日志留在 `build/*.log`；`PASS expected failure` 代表成功复现了错误。只用 `make all` 时不会触发这些故意失败的命令。

## 实验源码

| 编号 | 路径 | 核心问题 |
| --- | --- | --- |
| 01 | `labs/01_pipeline` | `.c → .i → .s → .o → executable` 各做了什么？ |
| 02 | `labs/02_symbols` | 符号、节、重定位如何把两个目标文件拼起来？ |
| 03 | `labs/03_archive` | 为什么 `.a` 的位置和成员划分会影响链接？ |
| 04 | `labs/04_shared` | `.so` 如何被查找，函数调用如何跨库解析？ |
| 05 | `labs/05_dlopen` | 显式运行时加载如何报告错误？ |
| 06 | `labs/06_memory` | ELF 文件与进程地址空间怎样对应？ |
| 07 | `labs/07_runtime` | `main` 前后发生了什么？退出方式有何差异？ |
| 08 | `labs/08_abi` | 为什么 C 和 C++ 看起来一样的函数链接不上？ |

工具：`gcc g++ make ar nm readelf objdump ldd`；`gdb` 是可选进阶工具。所有命令默认在本目录运行。构建产物放在 `build/`，`make clean` 仅删除该目录。修改源码后重新运行 `make all`，若改了 Makefile 编译选项则执行 `make clean && make all`。不要在不可信二进制上使用本材料中的运行、`ldd` 或预加载命令。
