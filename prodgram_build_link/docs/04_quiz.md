1. `gcc -c main.c` 成功能否证明最终程序可执行？
2. `.bss` 没有保存全部零字节，运行时是否不占空间？
3. section 和 segment 分别解决什么问题？
4. `extern int shared;` 与 `int shared = 7;` 有什么区别？
5. 链接器已经知道函数名字，为什么还需要重定位？
6. 为什么静态库放在引用它的目标文件前面可能链接失败？
7. 链接自制 `.a` 后，程序是否就不需要任何 `.so`？
8. `-L./lib` 能否保证程序运行时找到 `./lib` 中的库？
9. PIC、GOT、PLT 分别起什么作用？所有调用都走 PLT 吗？
10. 为什么 LD_PRELOAD 能让实验 04 输出 100？
11. dlopen 成功是否代表 dlsym 查询 plugin_value 一定成功？
12. malloc 返回的地址为什么不一定在 maps 标注的 `[heap]` 内？
13. main 是 ELF 入口吗？哪些行为能发生在 main 之前？
14. return、exit、_Exit 对实验 07 的自动对象、全局对象和回调有何影响？
15. extern "C" 解决了什么，没解决什么？

<summary>完成后展开参考答案</summary>

1. 不能。`-c` 允许留下外部符号引用；最终链接可能找不到定义，装载时还可能找不到动态依赖。看实验 02。
2. 会需要虚拟地址空间，访问后可能消耗物理页。NOBITS 节减少文件中的初始化零数据，不能理解为免费内存。看节大小和 LOAD 的 MemSiz。
3. section 用于链接组织与分析；segment 描述运行时映射，一个 segment 可以包含多个 section。看 `readelf -SW/-lW`。
4. 前者是声明，使用时形成对外部定义的引用；后者提供已初始化定义。看两个目标文件的 U 与 D。
5. 名字只解决引用与定义的匹配；机器指令或数据里仍需填入地址/偏移。看实验 02 的重定位和最终反汇编。
6. 归档被扫描时还没有需要该成员的未定义引用，可能不抽取；后面的引用出现时不自动按照你期望重扫该库。看实验 03。
7. 不一定。只把该归档中所需成员纳入结果，libc 等仍可为动态依赖。检查动态节。
8. 不能。-L 是构建时的搜索路径，运行时依赖动态链接器的路径规则。看 NEEDED、RUNPATH 和搬家实验。
9. PIC 支持不同装载地址；GOT 存放间接寻址需要的信息；PLT 常用于跨对象函数调用的跳转/绑定。具体路径受架构和选项影响，并非所有调用都经过 PLT。
10. 动态链接器在本实验的符号查找过程中优先找到预加载库的 answer，默认可抢占符号被该实现满足。用 bindings 日志验证。
11. 不代表。库可能根本没导出该名字；查 dlerror 和动态符号表。实验用 libanswer.so 演示这一区别。
12. 分配器可能通过 mmap 或其他管理区域满足请求；heap 标签不覆盖所有动态分配。以返回地址和 maps 的对应关系验证。
13. 通常不是。启动代码、动态装载和初始化参与建立执行环境；全局对象构造可以先于 main。对比 ELF 入口、_start 和 main。
14. return 会先析构 main 的自动对象，再正常退出；exit 不析构当前栈上的自动对象，但执行正常退出处理；_Exit 跳过常规析构与回调。看三个输出顺序。
15. 解决语言链接约定，典型用途是 C/C++ 符号匹配；不保证布局、异常、STL ABI、分配释放规则都兼容。对比原始符号名。

## 综合题：用十句话讲完

假设 main.cpp 调用了 libdemo.a 中的函数，该函数又调用 libhelper.so：解释构建时谁提供符号、静态库抽取什么、可执行文件保留哪些动态信息、启动时谁找库、函数调用如何到达实现、哪些问题会在哪个阶段暴露。允许用实际命令辅助，但最终要能脱离笔记讲清楚。

合格答案应涉及：声明与定义、目标文件、归档成员抽取、库顺序、重定位、NEEDED、运行时搜索路径、动态链接器、入口与运行库、main。不要强行断言所有函数都首次调用时解析。
