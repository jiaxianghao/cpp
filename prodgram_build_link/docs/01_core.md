# 知识主线：从源代码到进程

## 1. 先记住这条因果链

```text
源代码 --预处理--> 展开后的 C/C++ --编译--> 汇编 --汇编--> 可重定位目标文件
                                     目标文件 + 库 --链接--> ELF 可执行文件
内核处理 exec 请求 --> 映射 ELF 的装载段、安排解释器
动态链接器 --> 装入依赖库、完成必要重定位及初始化流程
程序启动代码与运行库 --> main --> 退出清理
```

这些是职责划分，不意味着每一步一定启动独立进程或生成磁盘中间文件。`gcc main.c -o app` 是驱动程序替你组织多步工作；`gcc` 不等于单一的编译阶段。

本课程用动态链接程序观察 Linux 用户态流程。静态链接程序通常没有同样的 ELF 解释器依赖；不能把所有 ELF 的启动过程都说成一模一样。

## 2. 目标文件里有什么

`.o` 不只是机器指令，它还带有数据、符号表和重定位信息。这里的关键问题是：代码生成时，编译器尚不知道另一个文件的函数最终在哪里。

| 常见节 | 意义 | 实验观察 |
| --- | --- | --- |
| `.text` | 机器指令 | `objdump -d` |
| `.data` | 可写的已初始化数据 | `shared = 7` |
| `.bss` | 通常为零初始化的静态存储数据 | `zero_area`，类型通常为 NOBITS |
| `.rodata` | 只读常量 | `label` |
| `.symtab` | 链接/分析用的符号表 | `readelf -s`、`nm` |
| `.dynsym` | 动态链接需要的符号 | `readelf --dyn-syms`、`nm -D` |
| `.rela.*` | 本平台的重定位项 | `readelf -r` |

节名和具体划分受工具链与选项影响；零值对象不必永远以同样方式放置。BSS 通常不为每个零在文件里保存一个字节，但进程仍需要对应的虚拟地址空间；被访问后可能消耗实际物理页。

**section 面向链接组织，segment 面向运行时映射。** 可执行文件的一个 LOAD segment 常包含多个 section。装载看 program headers，而不是把每个 section 独立映射一遍。

## 3. 符号解决“找谁”，重定位解决“怎么填地址”

`extern int shared;` 是声明并允许引用，`int shared = 7;` 提供定义。链接器用符号解析把引用匹配到定义，再依据布局修补需要地址的地方。

`nm` 常见标记：`U` 为未定义引用，`T` 为代码定义，`D` 为数据，`B` 为 BSS；小写通常代表局部符号，具体含义看符号类别。实验中的文件级 `static local_bias` 有内部链接，不能当成另一个目标文件的外部定义。

一个重定位项描述“哪个位置、引用哪个符号、用什么计算方式”。x86_64 的一些 PC 相对重定位可以理解为 `S + A - P`：符号地址 + 加数 - 修补位置地址。不同重定位类型有不同公式，不能套用一个公式处理全部情况。

实验 02 在 `-O0` 下禁用 PIE，是为了让链接前后更容易对照；不代表正式项目必须禁用 PIE。目标文件里暂存的立即数或偏移并不一定是最终地址。

常见强定义冲突会报 multiple definition；缺少需要的定义会报 undefined reference。弱符号、COMMON 等存在额外规则；当前复习先用明确初始化的强定义避免把工具链默认值混进概念。头文件里放普通全局变量定义，可能让每个包含它的文件都产生一个定义。

## 4. 静态库就是带索引的目标文件归档

`.a` 不是一种可以直接装载运行的格式。链接器通常按当前未解决的引用从归档中抽取需要的成员；普通 `.o` 输入与按需抽取的归档行为不同。

对 GNU 链接器，命令行从左到右处理时，库出现得过早可能尚无引用需要它，后面的引用因此得不到满足。通常把引用方放前、提供方放后。库间循环依赖可以用链接组处理，但应先理解依赖结构。

本实验每个函数分属不同成员，因此 `unused.o` 不会被抽取。如果两个函数放进同一个 `.o`，成员被抽取时两个函数可能一起进入结果；函数节与垃圾回收又是另一层机制。

**链接了自己的 `.a` 不等于整个程序完全静态链接。** 实验 03 仍可能动态依赖 libc。

## 5. 动态链接把一部分解析推迟到运行时

`-L` 告诉链接器构建时去哪里找库；它不会自动变成运行时查找路径。动态 ELF 会记录 NEEDED 等信息，运行时动态链接器再去寻找依赖。

实验显式生成 RUNPATH=`$ORIGIN`，让加载器在可执行文件所在目录查找直接依赖。这里 `$ORIGIN` 由动态链接器解释，不是 shell 的变量。Makefile 中要写成 `$$ORIGIN` 再用单引号保护 shell 展开。

Linux/glibc 中，普通执行情况下，LD_LIBRARY_PATH 可参与并优先于 RUNPATH 的查找；RPATH、RUNPATH、系统缓存、默认目录以及带斜杠的依赖名各有不同规则。RUNPATH 主要用于对象的直接依赖，不应当假设它自动传播给所有传递依赖。安全执行模式还会限制环境变量。

PIC 使代码能够在不同加载地址下运行，常通过 PC 相对寻址、GOT 等机制减少代码段上的运行时地址修改。共享的是适合共享的代码页等，**不是不同进程共享同一份可写全局变量**。

GOT 可保存运行时解析的地址；PLT 常用于外部函数调用跳转。传统惰性绑定会在首次调用时解析某些函数，立即绑定则更早处理。工具链与安全选项会改变路径，所以以本机 `objdump` 和动态信息为准；不是所有动态调用都必然经过同一种 PLT。

`LD_PRELOAD` 演示默认可抢占符号的解析顺序：程序尚未改动，`answer` 却可被另一个库提供。隐藏符号、库内部绑定、静态链接等情形不能照搬此结论。

`dlopen` 是程序显式请求装库，`dlsym` 按名字查导出符号；普通链接依赖主要由 NEEDED 描述，两者都利用动态链接器，但触发时机和错误处理接口不同。

## 6. 文件地址不等于进程地址，更不等于物理地址

ELF 文件偏移说明字节在文件中哪里；虚拟地址说明进程如何寻址。LOAD 段通过文件偏移、虚拟地址、权限、文件大小和内存大小描述映射需求。内存大小大于文件大小的部分可用于零填充区域。

进程有独立的虚拟地址空间。ASLR 与 PIE 会让某些地址在多次运行时变化；固定地址观察不能替代分析。相同虚拟地址也不意味着两个进程使用同一物理页。

栈用于调用现场和常见自动变量；堆是动态分配的常见来源。`malloc` 是分配器接口，可能复用内存、扩展 brk 区域或使用 mmap。大块内存是否单独 mmap 与分配器策略、阈值、历史状态有关，不能只凭块大小断定。

`free` 释放分配器层面的所有权，不保证马上把内存归还操作系统，也不保证 RSS 立即下降。

## 7. main 不是程序真正入口

典型 GNU/Linux 程序从 ELF 入口对应的启动代码开始，运行库参与建立 C/C++ 执行环境。全局 C++ 对象的构造可以先于 `main`；具体工作由动态链接器、启动代码和运行库共同完成。

`return` 离开 `main` 会先销毁它的自动对象，再进入正常退出处理。直接调用 `std::exit` 进入正常退出处理，但不会展开当前调用栈并析构这些自动对象。`std::_Exit` 跳过常规退出回调和对象析构；实验先 fflush，以免缓冲输出掩盖区别。

本实验的单个全局对象与回调具有明确的注册顺序。不要把它推广成“所有全局对象跨编译单元都有稳定初始化顺序”。运行库还承担标准 I/O、分配、异常支持等工作；调用 `printf` 不等于直接执行一个系统调用。

## 8. ABI 是二进制层面的约定

ABI 包含符号命名、调用约定、参数与返回值传递、布局与对齐等。C++ 的重载需要在本平台通过名字修饰表达参数类型等信息，因此 C 与 C++ 源码里同名函数可能不是同一个链接符号。

`extern "C"` 指定 C 语言链接，让适合的接口按 C 的链接约定暴露；它不把 C++ 类型、异常、STL 容器自动变成稳定的 C 接口。跨库接口还需考虑编译器 ABI、对象生命周期和由谁分配/释放内存。

本轮只验证符号命名这一层。符号成功链接是兼容的必要条件之一，不能独自证明完整 ABI 兼容。
